# 03 - 描述新增 `content` 字段

**What to build:** `pzt eval` 除了现有的质量评价之外，还产出一段**画面内容描述** - 这张照片里发生了什么、有谁、在哪、什么氛围。这段描述存进库、出现在 headless 的 JSON 输出里，供后续的选片与文案使用。

现有的 `assessment` 覆盖的是构图/色彩/对焦/摄影审美，即"拍得怎么样"，回答不了"画面里有什么"。后续所有基于意图的选片都依赖后者。

**内容与质量必须是两个独立字段，不能合并**（PRD 决策四）：

1. TUI 的"AI 点评"面板按显示宽度硬换行，且装不下的部分**静默不画**。合并会让超出的内容无声消失。
2. 坐在 TUI 前的人正看着照片，不需要"这张照片里有什么"的文字复述。内容描述只为看不见照片的机器存在。

因此 **`content` 不进 TUI**，`assessment` 的语义、长度与显示一字不变。

描述的形状在**三处**被定义：面向模型的提示词、schema 说明、以及本地模型走的**约束解码 JSON Schema**。漏掉第三处会让本地模型不稳定地吐这个字段。

内容描述的提示词必须明确要求写"画面里发生了什么、有谁、在哪、什么氛围"，否则模型会顺着 `assessment` 的调子继续写摄影评语，两个字段变成同义反复（PRD 风险二，标为高风险）。

**Blocked by:** None - can start immediately.

**Status:** ready-for-agent

- [ ] `pzt eval --json` 的输出含 `content` 字段
- [ ] 库里落盘的评估记录含 `content`
- [ ] 走本地模型的约束解码时稳定产出 `content`（三处形状定义均已更新）
- [ ] 读取一条不含 `content` 的旧评估记录不报错，`content` 退化为空
- [ ] 表结构未改动，无迁移脚本
- [ ] TUI 的"AI 点评"面板显示内容与改动前一致，不含 `content`
- [ ] `assessment` 的提示词与语义未变
- [ ] 真机验证：`content` 写的是画面内容而非摄影评语，与 `assessment` 不重复
