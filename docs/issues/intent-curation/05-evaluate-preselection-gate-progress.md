# 05 - curate 内部评估预选集：闸门 + 进度 + 偿还语义折叠

**What to build:** `pzt curate --ai` 开始对**预选集**里的每张照片跑评估，于是它从一条纯本地计算的命令变成一条会花几分钟、会失败、会超时的命令。这一票把随之而来的三件事一次做齐：**开跑前问一句、跑的时候报进度、被拒绝时说清楚**。

选择逻辑本票不变，仍走确定性路径。本票交付的是"curate 现在会花钱，并且花钱这件事对用户是可见、可拒绝、可观测的"。

**开销闸门**：在任何视觉调用发生之前，把**合并后**的开销报给调用方（要比较多少次 + 要评估多少张），由调用方决定跑不跑。拒绝时零写入。用户心智里没有簇内簇外的区别，所以只问一次、报一个合并的数字（PRD 决策十七、十八）。

**进度**：评估期间往 stderr 的带外通道吐进度（沿用 T-8 建立的机制与 schema，SPEC §3.2）。agent 侧的渲染是票 09，本票只负责产生。

**同刀偿还一笔历史债**（PRD 决策十九，不可延后）：`core/curate/curate.h` 里写死了触发条件 - 给 curate 加上开跑闸门的那次改动，**必须在同一个改动里**让返回结构能表达"用户拒绝了"与"被取消了"。原因是现有代码里有一句提前返回，会把这两种情况与"候选池本来就是空的"折叠成同一个返回值。不修的后果是：用户在闸门上点"不跑"，agent 收到的东西与"这个项目里一张照片都没有"完全一样，会对用户说错话。

**顺序约束**：本票必须在 03 之后。缓存判据是"有评估记录就跳过"，若本票先落地，那批照片会写入没有内容描述的评估记录，且之后**永远不会被刷新**。

**Blocked by:** 03（描述新增 `content` 字段）、04（预选集裁剪与 M 旋钮）

## 落地记录

**闸门问在哪里，规格没写死，实现时拍板成两处。** PRD 决策十八只说"报合并后的开销"。锦标赛的闸门在 `tournament` 内部、分簇之后第一次比较之前，那是唯一能报出精确比较次数且拒绝后状态跟没跑过一样的位置；但它有个 `!groups.empty()` 的前提——对锦标赛而言没有 size>=2 的簇就没有开销，问了没意义。curate 不成立：全是单例簇时一次比较都不发，评估开销照样在。于是闸门有两个触发点，用一个 `gate_consulted` 标志保证**合起来只问一次**：有簇要比就由 tournament 那一路问，没有就由 curate 在评估之前补问。

**两路报出的精度不同，这是取舍不是疏漏。** tournament 那一路只能报预选集大小（上界）——闸门必须问在锦标赛之前，而预选集是从 winner 里裁出来的，那时还不知道 winner 是谁、无从查缓存。curate 补问那一路 winners 已经就是预选集，报的是扣掉缓存之后的精确张数。两者都只会高报不低报。

**`AiGateFn` 的载荷从两个平铺 int 改成 `AiCost` 结构体**（PRD 待 Eng Design 问题 3 的答案）。curate 算评估张数要用候选集大小，而那个数只有分簇跑完那一刻才有。dedup 侧只读原来那两个字段，行为一字未变。

**取消不是零写入。** 评估是逐张写库的，喊停时已评估完的那几张留在库里。dedup 的 `CancelFn` 文档承诺零写入（它把写库统一放在最后一步），这条路径做不到，也不该做——每条评估记录本身是完整的，留着正好被下次运行的缓存判据命中，回滚掉等于下次再花一次钱。零写入的承诺只对闸门（`ai_declined`）成立，那时一张都还没评估。

**测试手法偏离了 PRD 测试决策表。** 那张表给 `curate()` 端到端标的是"注入：否"。本票要覆盖的全部行为（闸门报的数对不对得上、缓存跳过、进度计数、取消）只存在于**成功路径**上，而这个文件既有的 AI 用例一律是"让调用必然失败、只验证退化"——正是 PRD 自己那条现状警告点名的。所以加了 `detail::curate_impl` + 可注入的 `EvaluateFn`，跟 `tournament::detail::cluster_and_choose_impl` 同一个先例。

## 未接线的两处（不在本票范围，但会影响 G5 何时可达）

1. **`pzt curate` 的 headless 路径给 `on_ai_gate` 传的是 `nullptr`**，跟 `pzt dedup --ai` 的 headless 路径同一处置（那边的闸门只在 `pzt open` 控制台里）。但 dedup 有 TUI 入口兜底，curate 按 SPEC §3.2 没有——所以闸门机制虽然在 core 就位、被测试覆盖，**真机上 `pzt curate --ai` 目前仍然不会问任何人**。本票的验收标准写的是"调用方"，core 层满足；PRD 的 G5（用户可以拒绝）要端到端可达，还缺一个决定：headless 没有交互式用户，闸门要么由 agent 经某种参数表达（PRD 决策九明确否掉了拆成两次调用），要么由 agent 侧现有的 Curate stage 对话闸门承担。**这个决定没有票认领**，06/07/08/09 都没提。
2. **`ai_declined`/`cancelled` 没有序列化进 `pzt curate` 的 JSON。** 当前两个钩子都是 nullptr，两个字段在 headless 上恒为 false，加进去是死字段。等第 1 条接线时一起补。
