# 05 - curate 内部评估预选集：闸门 + 进度 + 偿还语义折叠

**What to build:** `pzt curate --ai` 开始对**预选集**里的每张照片跑评估，于是它从一条纯本地计算的命令变成一条会花几分钟、会失败、会超时的命令。这一票把随之而来的三件事一次做齐：**开跑前问一句、跑的时候报进度、被拒绝时说清楚**。

选择逻辑本票不变，仍走确定性路径。本票交付的是"curate 现在会花钱，并且花钱这件事对用户是可见、可拒绝、可观测的"。

**开销闸门**：在任何视觉调用发生之前，把**合并后**的开销报给调用方（要比较多少次 + 要评估多少张），由调用方决定跑不跑。拒绝时零写入。用户心智里没有簇内簇外的区别，所以只问一次、报一个合并的数字（PRD 决策十七、十八）。

**进度**：评估期间往 stderr 的带外通道吐进度（沿用 T-8 建立的机制与 schema，SPEC §3.2）。agent 侧的渲染是票 09，本票只负责产生。

**同刀偿还一笔历史债**（PRD 决策十九，不可延后）：`core/curate/curate.h` 里写死了触发条件 - 给 curate 加上开跑闸门的那次改动，**必须在同一个改动里**让返回结构能表达"用户拒绝了"与"被取消了"。原因是现有代码里有一句提前返回，会把这两种情况与"候选池本来就是空的"折叠成同一个返回值。不修的后果是：用户在闸门上点"不跑"，agent 收到的东西与"这个项目里一张照片都没有"完全一样，会对用户说错话。

**顺序约束**：本票必须在 03 之后。缓存判据是"有评估记录就跳过"，若本票先落地，那批照片会写入没有内容描述的评估记录，且之后**永远不会被刷新**。

**Blocked by:** 03（描述新增 `content` 字段）、04（预选集裁剪与 M 旋钮）

**Status:** ready-for-agent

- [ ] `pzt curate --ai` 只评估预选集，评估次数与 04 算出的规模一致，与图库大小无关
- [ ] 闸门在任何视觉调用发生**之前**触发
- [ ] 闸门报出的比较次数与评估张数与实际执行的数量一致
- [ ] 调用方拒绝时零写入
- [ ] 调用方拒绝时，返回结构中"用户拒绝"与"候选池为空"可分辨
- [ ] 中途取消时，返回结构能表达"被取消"，与上一条互不混淆
- [ ] 评估期间按张往 stderr 吐进度行，格式符合 T-8 既定 schema
- [ ] 不开 AI 时不触发闸门、不跑评估、不产生进度行
- [ ] 已评估过的照片仍然跳过，不重复花钱
- [ ] `pzt dedup --ai` 的锦标赛路径与其闸门不受影响
