# 04 - 预选集裁剪与 M 旋钮

**What to build:** `pzt curate` 在从候选集里选片之前，先按多样性把候选集裁成一个**预选集**，规模是最终张数的若干倍。选择逻辑本身不变，只是它现在面对的是一个更小的池子。

这一票不涉及任何 AI，行为完全确定，但它是后续所有开销控制的地基：票 05 起评估只跑在预选集上，评估次数因此**由构造保证有界**，与图库大小无关。

预选集大小：

```
min(ceil(max(1.5, M) · N), 候选集大小)
```

- **M 进 settings**，默认 2，与既有的 curate 时间窗口/哈希阈值同类，由 CLI 读出后显式传进 core。
- **下界 1.5**：M 等于 1 时池子正好等于要选的数量，后续模型没有任何选择余地，那次调用纯属浪费。
- **上界是候选集大小，不设绝对条数上限**。依据：分簇已经压缩过一轮。
- 多样性只沿拍摄时间衡量（PRD 决策十二），这是预筛跑在评估之前的必然结果。

**测试缝隙**：把"候选集大小 + M + N → 预选集大小"做成不依赖数据库与网络的纯函数，表驱动穷举边界（PRD 测试决策）。
