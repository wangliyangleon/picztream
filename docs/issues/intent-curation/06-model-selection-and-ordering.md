# 06 - 模型选择与排序接进 curate

**What to build:** `pzt curate --ai` 的选择不再是随机抽样。模型读着预选集里每张照片的**质量评价与内容描述**，挑出用户要的 N 张，**并决定它们的先后顺序**。

这是整个增量的核心。今天开 AI 时选择是字面意义的 `std::sample`，代码自己写明了原因："没有质量分可比"。现在有描述可读了。

**这次 LLM 调用放在 core**，尽管它不看像素。分层轴已改述为"关于照片的推理归 core，关于用户的推理归 agent"，判据是输入里有没有照片信息（含照片的衍生描述）。取舍与被否掉的替代方案见 ADR-0001。core 现有的 LLM 调用路径都吃图，需要新开一条纯文本路径。

**选择与排序是同一次决定，不拆成两步**（PRD 决策十四）："开头结尾要呼应"这类叙事要求会反过来影响选哪几张，拆成"先选再排"会切在错误的地方。返回顺序即交付顺序。

**模型用序号标识照片**，不用文件路径（PRD 决策十三）：提示词把预选集编成 `1..K`，模型返回序号数组。幻觉面从任意字符串缩成"整数在不在范围内"，约束解码还能直接卡住类型。

**返回值按"清洗后判定"处理**：

1. 剔除越界序号、去重，**保序**
2. 剩余 ≥ N：取前 N，采纳
3. 剩余 < N：**整体退化**成确定性选择

不选"任何不合法就整体退化"（模型返回 9 个好序号外加 1 个越界的，整批扔掉丢的是真信号）；不选"不足时用确定性结果补齐"（补进来的照片既不符合用户偏好、也不在模型排的顺序里，交付的会是两套逻辑拼接的结果，而用户看到的话术只有一种）。

**整批退化的信号必须独立**（PRD 决策二十一）：不能复用既有的"某几个簇比较失败"计数器 - 那个计数器已进用户话术（"哪几组不是 AI 挑的"），混进去会让那句话直接说错。

**测试缝隙**：序号清洗与退化判定做成不依赖网络与数据库的纯函数，表驱动穷举边界。**注意现有 `curate` 的 AI 测试手法是让调用必然失败、只验证退化后的行为，成功路径从未被覆盖** - 本票的校验、排序、分界全在成功路径上，照抄现有手法等于零覆盖，需要注入式的假 HTTP 层（沿用 `core/ai` 各模块既有的 `detail::request_*_impl` 模式）。

**Blocked by:** 03（描述新增 `content` 字段）、04（预选集裁剪与 M 旋钮）、05（curate 内部评估预选集）

**Status:** ready-for-agent

- [ ] 开 AI 时选择结果不再来自随机抽样
- [ ] 模型的输入含每张照片的质量评价**与**内容描述两者
- [ ] 模型返回序号而非文件路径
- [ ] 返回含越界序号时，越界项被剔除，其余按原序采纳
- [ ] 返回含重复序号时，重复项被剔除且保序
- [ ] 清洗后有效序号 ≥ N 时取前 N
- [ ] 清洗后有效序号 < N 时整体退化成确定性选择
- [ ] 整批退化有独立信号，与"某几个簇比较失败"的既有计数器互不干扰
- [ ] 交付顺序等于模型返回的顺序，经 headless 输出保真
- [ ] 序号清洗与退化判定是纯函数，有表驱动边界用例，不需要网络或数据库
- [ ] 成功路径有覆盖（注入式假 HTTP），不只测退化
- [ ] 关 AI 的行为不受影响
